# Mac 权限迁移、截图与面试音频可靠性需求

## 1. 背景与问题

Mac 客户端当前存在两个 P0/P1 级问题：

1. 笔试截图能够进入分析流程，但悬浮窗最终只突出显示“本次处理失败”。现有内部链路包含捕获、队列保存、压缩、直传或 OSS 上传、后端分析、模型结果解析等多个阶段；失败信息虽部分写入本地日志和事件负载，但用户无法稳定看到、复制或导出完整的阶段、错误码与请求标识，导致实体 Mac 失败无法被准确归因。
2. 面试助手启动后可能在没有用户操作的情况下失去听写能力，并且系统扬声器音频可能未被采集。当前实现会在取得 `getDisplayMedia` 流后立即停止视频轨，没有处理系统音频轨的 `ended`/`mute`、`AudioContext` 挂起、隐藏采集窗口异常等运行期状态；WebSocket 重连状态也没有作为独立会话状态反馈给界面。因此界面可能仍显示“监听中”，实际已经没有可用音频或识别连接。

此前 Mac 云构建、ad-hoc 签名、权限文案和启动阶段检查只能证明包可构建及初始连接逻辑存在，不能替代实体 Mac 上的 TCC 权限、ScreenCaptureKit 音轨生命周期、睡眠/切换音源和真实扬声器回环验证。本次修复必须以可观测状态、自动恢复和实体 Mac 证据闭环，不能继续依赖重复试包猜测。

## 2. 目标

- 每一次截图失败都能定位到唯一阶段，并提供错误码、可执行恢复建议和脱敏请求标识。
- 截图分析失败时保留原截图，允许原请求安全重试，并保证失败不重复扣积分。
- 面试听写会话除用户主动停止、应用退出或不可恢复的系统权限终止外，不得自行结束。
- 麦克风、系统音频、音频处理和语音识别连接分别展示真实状态，禁止“界面显示监听但实际无音轨”。
- 可恢复的音轨、音频上下文或网络故障自动恢复；不可恢复时明确告诉用户需要重新授权或重新选择共享源。
- 形成 Apple Silicon 与 Intel 的构建证据，以及实体 Mac 的权限、真实扬声器和长时运行证据。

## 3. 范围

### 3.1 包含

- `desktop-core` 的截图编排、分析请求、错误模型、面试状态机、系统音频/麦克风采集、WebSocket 重连、界面状态与脱敏诊断。
- Mac 壳层的媒体权限、系统共享选择器、构建配置和双架构测试包。
- Windows 共享桌面逻辑的必要回归，确保共享核心改动不破坏已验证的 Windows 版本。
- 受影响的自动化测试、实体 Mac 测试步骤、回滚记录和隔离测试包。

### 3.2 不包含

- 不修改浏览器插件、Android、积分价格、支付、账号数据或数据库结构。
- 不修改生产官网、正式 Mac 更新清单或 Windows 更新通道，直到测试包通过并收到明确上线指令。
- 不以关闭 macOS 权限保护、绕过 TCC、隐藏答案或规避监考作为修复方案。
- QuizMate 自身执行题目截图时应避免把自身悬浮框合成进 AI 输入；但不实现或承诺让答案悬浮框对系统截图、第三方录屏、投屏或外接采集不可见。
- 本规格阶段不承诺 Apple Developer ID 正式签名和公证；若仍无证书，测试包必须继续明确标注 ad-hoc 签名限制。

## 4. 用户故事与验收标准

### R1. 截图分析端到端可诊断

作为 Mac 用户，我希望失败信息能告诉我失败发生在哪一步，以便一次性采取正确操作并把有效证据交给支持人员。

- 当截图或分析失败时，系统应展示用户可理解的失败阶段、稳定错误码、简短原因和一条可执行恢复建议。
- 当失败来自捕获、保存、压缩、上传、后端响应、超时、鉴权、积分或结果解析时，系统应将其分别归类，不得统一归为未知“处理失败”。
- 当后端返回请求标识时，系统应在界面和日志中显示脱敏请求标识；没有后端标识时应使用客户端生成的请求标识贯穿本次链路。
- 当用户复制诊断信息时，系统应输出版本、平台、架构、时间、阶段、错误码、请求标识和重试次数，不得包含截图正文、完整本地路径、账号令牌、API Key 或签名 URL。
- 当发生未知异常时，系统应记录原始异常类型和安全摘要，并以 `UNKNOWN` 作为最后兜底；不得静默吞掉异常。

### R2. 截图失败恢复与幂等

作为笔试助手用户，我希望失败后可以直接重试且不会丢图或重复扣积分。

- 当捕获成功但后续分析失败时，系统应保留截图队列和可重试状态。
- 当分析成功且结果已确认可展示时，系统才应清空对应截图。
- 当用户对同一次失败执行重试时，系统应使用稳定的幂等边界，保证后端最多结算一次、积分最多扣除一次。
- 当网络、超时或可重试的 5xx 错误发生时，系统应允许用户重试并显示当前重试次数；不得无限自动重试模型请求。
- 当图片为空、损坏或压缩后不可解码时，系统应在上传前终止并明确提示重新截图。

### R3. Mac 截图权限与捕获正确性

作为 Mac 用户，我希望客户端准确识别屏幕录制权限，并在权限变化后恢复截图。

- 当屏幕录制权限未决定时，系统应触发标准 macOS 授权流程并说明授权后是否需要完全退出重开。
- 当应用安装后首次启动时，系统应在进入工作台前展示一次性权限向导，主动检查屏幕录制和麦克风权限并执行可验证的授权步骤；不得等用户第一次进入笔试或面试功能时才开始说明权限。
- 当 macOS 要求用户点击或选择共享源才能授予能力时，权限向导应明确引导并等待用户操作，不得宣称安装器能够静默代授权。
- 当权限被拒绝或撤销时，系统应显示准确的系统设置路径，并保持图片上传等不依赖屏幕录制的功能可用。
- 当权限已允许时，系统应验证捕获图像非空、尺寸合理且不是权限黑屏，再进入队列。
- 当 QuizMate 自身执行题目截图时，系统应临时排除或隐藏自身悬浮框，验证输入图片不包含该悬浮框，并在捕获后恢复原显示状态。
- 当主捕获路径失败时，系统应记录每条回退路径的结果，但界面只展示最终根因和恢复建议。

### R4. 音源状态必须真实可见

作为面试助手用户，我希望知道麦克风和电脑声音是否真的在工作。

- 当开始面试时，系统应分别显示系统音频、麦克风、音频处理和语音识别连接的状态，不得只显示一个笼统“监听中”。
- 当首次启动权限向导运行时，系统应完成麦克风输入检测，并提供一次系统音频共享与电平测试；用户跳过系统音频测试时，正式面试功能应保持“尚未验证”而不是误报可用。
- 当正式模式启动时，系统必须确认存在活动的系统音频轨；若不存在，应拒绝进入“监听中”并明确提示重新选择共享源或开启系统音频。
- 当演示模式启动时，系统应确认麦克风轨可用；系统音频不可用时可以降级为仅麦克风，但必须持续显示降级状态。
- 当音轨处于静音但未结束时，系统应区分“当前无声音”和“音轨失效”，不得因为短暂无声自动停止会话。
- 当扬声器播放可识别的测试音频时，系统应提供可观测的系统音频电平或最近收到音频的时间，用于确认回环采集真实生效。

### R5. 面试会话生命周期

作为面试助手用户，我希望会话只在我明确停止时结束，临时故障由系统恢复。

- 当用户已成功开始面试且未点击停止时，系统应保持会话意图为运行中，即使 WebSocket、音轨或音频上下文短暂异常。
- 当用户点击停止、退出应用或明确切换到需要重建采集的模式时，系统才应结束当前会话意图并释放全部轨道、节点、定时器和连接。
- 当页面重新渲染、窗口隐藏、悬浮窗关闭或 React effect 卸载时，系统不得隐式停止仍由用户启动的面试会话。
- 当重复点击开始或停止时，系统应执行幂等操作，不得产生两个采集窗口、两套音轨或旧连接关闭新会话的竞态。
- 当发生不可恢复错误时，系统应进入“需要操作”状态而非伪装为正常监听，并保持错误详情可复制。

### R6. Mac 音轨与 AudioContext 自动恢复

作为 Mac 用户，我希望系统共享或后台调度变化不会悄悄让听写失效。

- 当系统音频或麦克风轨触发 `ended` 时，系统应识别具体音轨和原因；可重新申请时自动重建一次，不可自动恢复时要求用户重新选择共享源。
- 当音轨触发持续 `mute` 或长时间没有音频帧时，系统应先进行健康检查，不得直接把自然静音判定为故障。
- 当 `AudioContext` 进入 `suspended` 或 `interrupted` 状态时，系统应尝试 `resume()`；恢复失败时应重建音频图并更新状态。
- 当通过 `getDisplayMedia` 获取系统音频时，系统不得通过提前停止承载捕获会话的必要轨道而间接终止系统音频；所有轨道只应在会话结束或明确重建时统一释放。
- 当隐藏音频窗口崩溃、导航失败或被销毁时，主进程应检测并重建采集窗口，而不是继续返回虚假的运行状态。

### R7. WebSocket 重连与连续听写

作为面试助手用户，我希望网络抖动或识别服务主动断开后能够继续听写。

- 当 ASR WebSocket 非用户主动关闭时，系统应保持采集图存活并进入“正在重连”状态。
- 当重连成功时，系统应重新发送初始化请求和合法的首包头，恢复发送音频，并把状态更新为“识别中”。
- 当重连失败时，系统应采用有上限的退避重试；达到上限后进入“需要操作”并提供重试按钮，不得无限静默循环。
- 当旧 WebSocket 的延迟关闭事件到达时，系统不得关闭或覆盖新连接。
- 当连续运行至少 30 分钟、经历一次网络断开恢复和一次长时间静音后，系统应继续识别后续问题且不会自行停止。

### R8. 界面状态一致性

作为用户，我希望按钮、悬浮窗和真实后台状态一致。

- 当后台确认所有必需组件就绪后，界面才应显示“面试进行中”。
- 当后台处于授权、连接、重连、降级或需要操作状态时，主界面和悬浮窗应显示相同状态。
- 当后台状态变化时，界面应由后台事件更新，不得仅凭本地 `setListening(true/false)` 推测。
- 当开始面试部分失败时，系统应回滚已创建的临时资源，并保留可诊断错误；不得遗留假悬浮窗或孤立采集进程。
- 当用户关闭悬浮窗但未停止面试时，系统应按明确产品规则继续听写并在主界面提示；关闭悬浮窗本身不得等同停止会话。

### R9. 诊断日志与隐私

作为支持人员，我希望从一份脱敏日志中还原失败时间线。

- 当截图或面试会话开始时，系统应创建会话标识，并记录状态转换、轨道数量/状态、AudioContext 状态、WebSocket 关闭码、重连次数和最终结果。
- 当用户选择“复制诊断信息”或“打开日志目录”时，系统应提供本次会话的脱敏证据，不要求用户使用终端查找文件。
- 当日志写入失败时，系统不得影响业务流程，但应在界面提示诊断不可用。
- 日志不得记录音频内容、转写全文、截图内容、简历正文、完整文件路径、邮箱、完整令牌、API Key、支付数据或签名 URL。
- 日志应设置大小/数量上限并滚动清理，避免长期增长。

### R10. 测试、兼容与发布门禁

作为发布负责人，我希望新包只有在真实 Mac 证据闭环后才进入正式渠道。

- 当实现开始前，项目应在统一测试文档新增独立变更编号，并补充截图阶段错误、音轨结束、AudioContext 挂起、WebSocket 重连、状态一致性和日志脱敏用例。
- 当共享 `desktop-core` 被修改时，系统应通过 Windows Node/Web 类型检查、单元测试和受影响的桌面回归，确保已验证的 Windows 版本不回归。
- 当生成 Mac 测试包时，CI 应分别构建 Intel 和 Apple Silicon 产物，校验架构、版本、DMG 完整性和当前签名状态。
- 当 macOS 26 为当前主流目标系统时，CI 应在 macOS 26 runner 上实际启动挂载 DMG 内的应用并确认进程持续存活；应验证主程序与 Electron Framework/Helpers 的签名身份一致，禁止仅用 `codesign --deep --strict` 代替动态加载验证。
- 当没有 Apple Developer ID 正式签名/公证时，测试结论应明确标记限制，不得把 ad-hoc 签名等同于 Gatekeeper 正式通过。
- 当实体 Apple Silicon 与 Intel Mac 尚未完成权限、截图、真实扬声器、30 分钟持续听写、断网恢复、睡眠唤醒和回滚验证时，Mac 正式发布状态应为“阻塞”。
- 当测试包需要交付时，只能上传到 OSS `temp/` 隔离路径；不得修改官网、生产下载对象或 `mac/latest-mac.yml`。

### R11. 笔试与面试 AI 响应性能

作为笔试或面试用户，我希望客户端立即反馈进度，并将可控的本地等待压缩到最低。

- 当用户触发截图或开始面试时，系统应在 100ms 内更新本地状态，不得在无反馈状态下等待网络或模型。
- 当有效截图已经生成时，客户端捕获后处理、校验、压缩和请求准备的 P95 应不超过 1.5 秒；超过阈值时诊断日志应指出最慢阶段。
- 当截图压缩结果低于直传阈值时，系统应直接提交分析，避免不必要的 OSS 票据和上传往返。
- 当面试问题被最终提交时，客户端应在 300ms 内发起 AI 请求；并发槽可保护后端，但不得重新引入逐题串行排队。
- 当网络和生产模型配置正常时，笔试从有效截图完成到答案返回的目标为 P50 不超过 10 秒、P95 不超过 20 秒；面试从问题最终提交到答案返回的目标为 P50 不超过 8 秒、P95 不超过 15 秒。
- 当外部 ASR、模型或网络耗时导致目标未达成时，系统应分别记录客户端、网关、后端和模型阶段耗时，不得把外部耗时伪装为客户端卡死。
- 当 AI 请求失败、超时或被取消时，客户端应立即结束当前进度状态、保留可重试输入并遵守失败不扣分规则。

### R12. 旧包权限迁移与统一授权

作为从旧 ad-hoc 安装包升级的 Mac 用户，我希望替换安装后只通过一个入口完成权限修复，不再逐项手工测试。

- 当新权限流程首次在 `/Applications/QuizMate.app` 启动时，系统应在进入主界面之前执行一次旧权限迁移；迁移只允许重置 bundle ID `vip.quizmate.mac` 自身的 TCC 记录，不得重置其他应用权限。
- 当一次性迁移已经在相同签名身份下成功记录时，后续普通启动和正式升级不得重复清理权限；当 ad-hoc CDHash 或 Developer ID Team 身份发生变化时应重新迁移；当迁移命令失败时，系统应保留未完成状态并显示可恢复错误，不得伪造成功。
- 当应用从 DMG、下载目录或开发目录直接运行时，系统应要求先安装到 `/Applications`，不得在临时路径请求正式权限或写入迁移完成标记。
- 当用户点击一次“开始授权”时，系统应按麦克风、屏幕录制和系统音频顺序触发标准 macOS 授权并自动验证；不得要求用户逐项点击“授权并测试”或主动播放声音。
- 当麦克风或系统音频音轨处于 `live` 但当前静音时，系统应将能力视为可用但无活动声音；不得把零电平误判为权限拒绝。
- 当屏幕录制权限需要完全退出重开时，系统应提供一键重启并在重启后自动恢复授权检查。
- 当构建用于正式发布时，应用应使用固定 Developer ID Application 身份、Hardened Runtime 和 Apple notarization；无稳定 TeamIdentifier 的产物不得进入正式更新通道。

### R13. 悬浮窗输入隐私与捕获边界

作为使用悬浮窗的 Mac 用户，我希望悬浮窗不抢焦点、不拦截底层应用输入，并且 QuizMate 自己的截图不会把悬浮窗送给 AI。

- 当任一笔试或面试悬浮窗创建、显示、恢复或重建时，系统应设置 `focusable=false`、`setIgnoreMouseEvents(true, { forward: true })`、透明无阴影和 `showInactive()`，并在运行期验证/重设鼠标穿透状态。
- 当用户点击、滚动或移动鼠标经过悬浮窗时，事件应传递到底层应用；悬浮窗不得临时切换为可交互状态。
- 当 QuizMate 自己捕获题目屏幕时，系统应在捕获事务内隐藏或排除所有 QuizMate 悬浮窗，等待合成器完成后捕获，并在 `finally` 中恢复原可见状态。
- 当应用调用 Electron/macOS 公开内容保护能力时，系统应记录“已请求”和可读回的真实状态；无法读回时不得把请求成功描述为全局捕获排除已验证。
- 当任一悬浮窗首次显示前，系统应一次性应用 `setContentProtection(true)`、`setAlwaysOnTop(true, 'screen-saver')`、`setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true })`、输入穿透和不抢焦点策略，不得先显示未完成保护配置的窗口。
- 当用户切换 Space、进入或退出全屏应用、更换显示器、睡眠唤醒，或系统使窗口失去置顶状态时，系统应幂等恢复全工作区可见、全屏辅助窗口、`screen-saver` 置顶、输入穿透和内容保护请求；恢复过程不得激活窗口或抢走前台应用焦点。
- 当悬浮窗销毁或重建时，系统应清理旧窗口的定时器和事件监听，并把同一固定保护策略应用到新窗口；不得通过 Renderer IPC、设置项或页面状态关闭内容保护或鼠标穿透。
- 当运行时无法读取内容保护状态时，系统应把诊断状态标为“已请求、无法验证”；当读回明确为关闭或设置调用失败时，应标为“降级”并重试，不得伪造“已验证”。
- 当用户通过快捷键调整悬浮窗位置或尺寸时，系统应保留现有可移动、可缩放能力；不得照搬参考产品的 `resizable=false` 而破坏现有交互。
- 系统不得加入私有 CGS API、进程注入、Hook、反监考或第三方捕获规避逻辑，也不得承诺对任意第三方 ScreenCaptureKit、硬件录制或投屏全局不可见。

## 5. 必测场景

1. 截图：允许/拒绝/撤销屏幕录制权限；有效截图；黑屏/空图；保存失败；压缩失败；直传失败；OSS 上传失败；后端 401/402/408/413/5xx；模型空结果/非法结果；失败后同图重试。
2. 音频：正式模式有/无系统音轨；演示模式双轨与仅麦克风降级；用户停止共享；音轨 `ended`/持续 `mute`；AudioContext `suspended`/恢复；隐藏窗口销毁后恢复。
3. 网络：启动阶段断网、运行中断网、ASR 主动关闭、重连成功、连续重连失败、旧连接延迟事件。
4. 生命周期：重复开始/停止、切换模式、关闭悬浮窗、隐藏主窗口、睡眠唤醒、切换输出设备、30 分钟持续运行。
5. 隐私：日志和复制诊断信息的敏感字段扫描；日志滚动；截图/音频/简历正文不落诊断。
6. 平台：Apple Silicon、Intel、Windows 共享核心回归；上一稳定 Mac 版本回滚或卸载重装。
7. 首次启动：全新安装后立即执行权限向导；允许、拒绝、跳过、授权后重启和升级保留状态；验证权限向导不会伪造系统权限结果。
8. 性能：同一固定题图与固定面试问题分别执行至少 20 次，记录 P50/P95、客户端阶段耗时和外部服务耗时；失败样本保留并解释。
9. 权限迁移：旧 ad-hoc 已授权包覆盖安装；迁移命令成功/失败；重复启动幂等；非 `/Applications` 启动；拒绝后恢复；授权后自动重启。
10. 悬浮窗输入与空间：笔试/面试窗口创建、首次显示、隐藏再显示、崩溃重建、Space 切换、全屏进入/退出、多显示器迁移和睡眠唤醒后的鼠标穿透、全工作区可见与 `screen-saver` 置顶恢复；QuizMate 自有截图前后窗口状态恢复。
11. 内容保护兼容：在支持的实体 Mac 上分别记录系统截图、命令行截图及可用的 ScreenCaptureKit 应用结果；“公开 API 已请求/已读回”与“具体捕获工具实测结果”分开记录，第三方或硬件链路失败不得被改写为代码级通过。

## 6. 成功标准

- 用户提供的截图失败可由界面/诊断信息确定唯一失败阶段和错误码，不再依赖猜测。
- 实体 Mac 上系统扬声器播放内容能被识别，且 UI 显示系统音频实际有输入。
- 面试听写连续运行 30 分钟，并在一次网络中断恢复、一次长静音和一次窗口隐藏后继续识别。
- 用户主动停止前没有无解释的会话终止；不可恢复故障均进入明确“需要操作”状态。
- 全新安装后首次启动即完成或明确跳过权限向导；未验证的权限在功能入口保持真实标记。
- 笔试与面试性能样本达到 R11 目标，或明确证明瓶颈位于外部服务并完成可控客户端路径优化。
- 受影响自动化、P0 冒烟、桌面兼容和回滚用例有脱敏证据；任何 P0/P1 失败时不发布正式版本。

## 7. 当前待确认的产品规则

本规格采用以下默认规则：关闭面试悬浮窗不停止听写；正式模式必须有系统音频，演示模式允许在明确提示后降级为仅麦克风；可恢复故障自动重试，不可恢复故障要求用户操作。若产品期望不同，应在进入技术设计前调整。
