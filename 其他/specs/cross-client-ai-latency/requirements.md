# 三端 AI 调用提速与本地知识库需求

## 1. 背景与目标

QuizMate 当前在 Windows、macOS 和 Android 客户端中通过截图压缩、OSS 上传、服务端图像识别和主模型作答完成分析。现有知识库上传、服务端存储、检索和注入模型上下文不再需要。

本次目标：

1. 缩短三端从发起分析到看到结果的等待时间。
2. 保留知识库上传入口和文件列表体验，但知识库完全改为客户端本地功能。
3. 后端停止存储、查询和调用知识库，知识库内容永不进入 AI 请求。
4. 保持账号、积分、幂等扣费、截图权限和 OSS 安全边界不变。

## 2. 范围

### 2.1 包含

- Windows Electron 客户端。
- macOS Electron 客户端。
- Android 客户端。
- 阿里云统一入口 `study-auth-api`。
- 阿里云主 API 的分析链路和知识库兼容动作。
- 三端与共享后端的自动化、构建、兼容和回滚验证。

### 2.2 不包含

- 浏览器插件代码修改。
- 客服系统自己的知识库。
- 数据库删表或删除既有知识库数据。
- 修改积分价格、登录方式、支付流程或模型密钥。
- 在客户端真实解析、向量化或调用本地知识库内容。

## 3. 用户故事与验收标准

### 需求 1：知识库仅保存在客户端

作为用户，我希望知识库上传入口仍然存在，以便在客户端看到自己选择过的文件，但文件不上传服务器，也不参与 AI 分析。

- 当登录用户选择受支持的知识库文件时，客户端应将文件复制到应用私有目录，并在本地列表显示文件名、类型、大小和添加时间。
- 当客户端重新启动且仍为同一账号时，客户端应恢复该账号的本地知识库列表。
- 当切换账号时，客户端应只展示当前账号在本机添加的文件，不得把另一账号的本地文件显示出来。
- 当用户删除本地知识库文件时，客户端应删除应用私有目录中的对应副本和本地元数据，不得调用远程删除接口。
- 当用户添加、列出或删除知识库文件时，客户端不得调用知识库上传、列表、删除或检索网络接口。
- 客户端日志不得记录知识库正文、完整本地路径或其他用户的文件元数据。
- 知识库文件不得出现在分析请求、提示词、页面上下文、截图元数据或模型请求中。

### 需求 2：后端知识库变为兼容空实现

作为系统维护者，我希望新客户端不依赖知识库后端，同时旧客户端不会因接口消失而直接崩溃。

- 当主 API 处理分析请求时，系统不得查询 `knowledge_docs` 或 `knowledge_chunks`，并应始终以无知识库上下文调用模型。
- 当主 API 返回分析结果时，兼容字段 `usedKnowledge` 应为 `false`，`knowledgeHits` 应为空数组。
- 当兼容期旧客户端调用知识库上传、列表或删除动作时，接口应返回可解析的空实现结果，不得写入数据库、对象存储或模型上下文。
- 本次变更不得自动删除现有数据库表、OSS 对象或历史知识库记录；这些内容仅作为回滚保留，后续清理必须单独授权。

### 需求 3：三端统一减少分析前等待

作为用户，我希望点击分析后立即进入处理状态，并减少模型调用前不必要的网络等待。

- 当用户发起分析时，Windows、macOS 和 Android 客户端应立即显示处理状态，不得等待积分预查完成后才更新界面。
- 当客户端准备发起分析时，不应单独调用积分预查作为必经步骤；最终余额和是否可分析由服务端分析接口权威判断。
- 当服务端返回积分不足时，客户端应显示明确提示且不得自行修改余额。
- 当用户取消、断网、超时或重复点击时，客户端应保持现有取消、互斥和幂等扣费保护。

### 需求 4：三端统一优化截图体积

作为用户，我希望截图上传更快，同时保持题目文字和公式清晰可识别。

- 当客户端上传截图时，应优先使用用户选定的题目区域；无法选择区域时才使用全屏截图。
- 当截图超过目标尺寸时，客户端应等比例缩放，最长边不超过 1600 像素。
- 客户端应使用适合文字识别的 JPEG 压缩，默认质量处于 70～80 区间，并以约 150～380 KB 为目标，而不是无条件压低画质。
- Windows、macOS 和 Android 应使用一致的体积上限和图片类型规则。
- 当压缩失败或图片仍超过服务端上限时，客户端应在上传前提示，不得发送已知无效请求。

### 需求 5：优化 OSS 与识别链路

作为用户，我希望上传后的图片尽量少经过重复传输和串行处理。

- 当客户端上传完成时，分析请求应提交受校验的 `objectKey` 和必要元数据，不应依赖客户端传递任意公网图片地址。
- 当网关读取同地域 OSS 图片时，应优先通过服务端受信任的 OSS SDK/内网访问读取对象，避免通过公网签名 URL 回下载。
- 当图片主要是清晰文字时，网关应优先使用本地 OCR；当 OCR 结果过短、明显无效或图片包含复杂公式、表格、图形时，系统才应回退到视觉模型。
- 当 OCR 或视觉识别完成时，系统应只把识别文本交给主模型，不得附加知识库内容。
- 当任一步骤失败时，系统应保持“不成功不扣积分”的现有结算规则。

### 需求 6：可观测性与性能验收

作为维护者，我希望知道等待时间消耗在哪个阶段，而不是仅看到一个总超时。

- 每次分析应生成同一个脱敏请求编号，并记录压缩、申请上传地址、OSS 上传、鉴权、OSS 读取、OCR、视觉回退、主模型和结算的分段耗时。
- 日志不得包含截图内容、知识库正文、完整令牌、模型密钥或 OSS 签名 URL。
- 自动化测试应验证纯文字 OCR 路径不调用视觉模型，OCR 失败路径最多回退一次视觉模型，分析路径不执行知识库查询。
- 性能对比应以相同测试图片记录改动前后总耗时和各阶段耗时；没有生产或隔离测试环境证据时，不得宣称具体百分比提升。

### 需求 7：生产构建与部署

作为产品负责人，我希望验证通过的优化版本部署到生产环境，并更新 Windows、macOS 和 Android 的正式下载产物。

- 当后端自动化测试、构建、兼容检查和回滚检查通过后，系统应先备份当前生产程序和配置，再以可回滚方式部署网关和主 API。
- 当后端部署完成时，系统应验证健康检查、未登录拒绝、知识库空实现、截图上传票据、OCR/视觉回退和分析积分契约。
- 当三端构建检查通过后，应生成新的 Windows、macOS 和 Android 产物，记录版本、大小和 SHA-256，并更新官网正式下载文件。
- 当更新官网下载文件时，应保留上一稳定产物作为回滚包，并验证公网下载文件与本地产物哈希一致。
- macOS 正式发布必须经过真实 Mac 的构建、签名、公证、stapling 和启动验证；若当前没有可用的真实 Mac 或签名条件，该平台必须标记为阻塞，不得虚报通过。
- 生产部署不得修改或输出模型密钥、OSS 凭据、账号令牌、支付密钥或其他生产秘密。
- 当任一 P0/P1 自动化或生产冒烟失败时，应停止后续发布并按回滚方案恢复上一稳定版本。

## 4. 平台约束

- Windows 与 macOS 共享 Electron 业务逻辑时，应优先抽取共享实现，避免两端产生不同协议。
- macOS 的构建、签名、公证和实机权限结果必须在真实 Mac 上验证；Windows 环境只能记录为阻塞。
- Android 本地文件必须保存到应用私有目录，不申请与本功能无关的额外存储权限。
- 浏览器插件保持冻结；共享后端的兼容空实现必须避免当前插件因响应字段缺失而崩溃。

## 5. 回滚边界

- 客户端代码可回滚到当前版本；本地知识库目录为新增非权威数据，旧版应安全忽略。
- 后端回滚后仍可读取既有知识库表，因为本次不删表、不迁移、不清理历史数据。
- 新后端必须保持上一稳定版 Windows、macOS、Android 和当前浏览器插件的登录、分析及积分协议可解析。
- 回滚前后必须验证成功分析只扣一次、失败不扣分、余额与流水一致。

## 6. 明确决策

- “本地知识库”只是本地文件管理与展示，不参与答案生成。
- 新客户端不会调用任何知识库远程接口。
- 后端知识库接口只为旧客户端协议兼容保留空实现。
- 既有服务端知识库数据本次不删除。
- 本次实现完成并通过发布门禁后部署生产后端，更新三端正式下载产物；macOS 仍受真实 Mac 签名、公证和实机验证门禁约束。
