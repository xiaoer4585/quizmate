## 一、构建测试

### 1.1 构建前检查
- [ ] `package.json` 中 `productName` 设置为 `"QuizCoze"`
- [ ] `package.json` 中 `main` 设置为 `"dist-electron/main.js"`
- [ ] `resources/icon.ico` 文件存在且是最新图标
- [ ] `build.files` 包含 `dist/**/*`, `dist-electron/**/*`, `resources/**/*`
- [ ] `build.asarUnpack` 包含 `node_modules/screenshot-desktop/**/*` 和 `node_modules/koffi/**/*`

### 1.2 构建步骤
```powershell
# 1. 创建英文路径 junction（避免中文路径导致 7za.exe 失败）
$asciiPath = "C:\QuizCozeBuild"
if (Test-Path $asciiPath) { (Get-Item $asciiPath).Delete() }
New-Item -ItemType Junction -Path $asciiPath -Target "e:\ai项目\考试插件\windows2.0\新一代\QuizCoze-New" | Out-Null

# 2. 构建 renderer + electron
cd C:\QuizCozeBuild
& "C:\Program Files\nodejs\npm.cmd" run build:renderer

# 3. 一次性构建安装包（不要分 --dir + --prepackaged 两步！）
node node_modules/electron-builder/cli.js --win

# 4. 复制安装包到新一代文件夹
Copy-Item "release\QuizCoze Setup 2025.11.16.exe" "e:\ai项目\考试插件\windows2.0\新一代\" -Force

# 5. 清理 junction
(Get-Item $asciiPath).Delete()
```

### 1.3 构建后验证（关键！）
- [ ] `win-unpacked\QuizCoze.exe` 存在（不是 `electron.exe`）
- [ ] `win-unpacked\resources\app.asar` 存在且大小 > 20MB
- [ ] `win-unpacked\resources\app.asar.unpacked\node_modules\koffi\` 存在
- [ ] `win-unpacked\resources\app.asar.unpacked\node_modules\screenshot-desktop\` 存在
- [ ] 安装包 `.exe` 文件大小 > 80MB
- [ ] **安装后检查**: `C:\Users\Administrator\AppData\Local\Programs\QuizCoze\resources\app.asar` 存在

### 1.4 常见构建问题
| 问题 | 原因 | 解决方案 |
|------|------|----------|
| `app.asar` 被占用无法删除 | QuizCoze 进程仍在运行 | `Get-Process QuizCoze \| Stop-Process -Force` |
| `electron.exe` 没有重命名为 `QuizCoze.exe` | `productName` 未设置 | 在 package.json 中设置 `productName: "QuizCoze"` |
| 安装后 `app.asar` 丢失 | 手动创建 7z 包时遗漏 | **不要手动创建 7z 包**，让 electron-builder 自己处理 |
| 7za.exe 报中文路径错误 | 路径包含中文字符 | 使用 junction 创建英文路径 `C:\QuizCozeBuild` |
| 图标显示为 electron 默认图标 | `--prepackaged` 模式不应用图标 | 一次性构建 `electron-builder --win`，不要用 `--prepackaged` |
| 图标显示为旧版本（缓存） | Windows 图标缓存未刷新 | 执行 `ie4uinit.exe -show`，或重启电脑 |

## 七、问题历史记录

### 2026-07-18 修复的问题

#### 问题1: 悬浮框被截屏捕获
- **现象**: 悬浮框能显示，但截屏/录屏能看到它
- **根因**: 没有调用 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`
- **修复**: 新建 `Win32Protection.ts`，使用 koffi 调用 Win32 API
- **状态**: ✅ 已修复

#### 问题2: 安装后打不开（闪退）
- **现象**: 安装后双击快捷方式无法启动
- **根因**: 安装目录 `resources\app.asar` 丢失
- **原因**: 手动创建 7z 包时遗漏了 app.asar
- **修复**:
  1. 设置 `productName: "QuizCoze"` 让 electron-builder 自动重命名 exe
  2. 不再分 `--dir` + `--prepackaged` 两步构建
  3. 一次性运行 `electron-builder --win` 让它自己处理 asar 打包
- **状态**: ✅ 已修复

#### 问题3: 快捷键不起作用
- **现象**: 调节透明度、大小、位置的快捷键无响应
- **根因**: 快捷键只在悬浮框启动后才注册；托盘"隐藏悬浮框"会销毁窗口并注销快捷键
- **修复**: 托盘 `toggleOverlay` 改为显示/隐藏切换（与 Ctrl+B 语义一致），不再销毁悬浮框
- **状态**: ✅ 已修复

#### 问题4: 后台管理与悬浮框不能同时存在
- **现象**: 启动悬浮框后后台管理窗口被关闭
- **根因**: `launchExamClient()` 调用 `closeEntryWindows()` 强制关闭配置窗口；`overlayLocked` 阻止重新打开
- **修复**:
  1. 移除 `launchExamClient()` 中的 `closeEntryWindows()` 调用
  2. 移除 `createLoginWindow()` 和 `createConfigWindow()` 中的 `overlayLocked` 守卫
  3. 修改 `handleWindowClosed()` 不再强制恢复配置窗口
- **状态**: ✅ 已修复

#### 问题5: 截图传给AI不起作用
- **现象**: 截图后搜题，AI 无响应
- **根因**: 多个 bug 叠加
- **修复**:
  1. `ScreenshotHelper.ts`: 修复 PowerShell 降级脚本缺少 `Add-Type -AssemblyName System.Windows.Forms`
  2. `ProcessingHelper.ts`: 修复 `checkCredits()` 网络失败时误判积分不足
  3. `ipcHandlers.ts`: 统一 IPC 截图与快捷键截图流程（都先隐藏悬浮框）
  4. `main.ts`: 悬浮框创建后立即同步 processingHelper 的 mainWindow 引用
- **状态**: ✅ 已修复

#### 问题6: 图标回到旧版本
- **现象**: 安装包或 exe 图标显示为 electron 默认图标
- **根因**: 使用 `--prepackaged` 模式构建时不应用图标配置
- **修复**: 一次性构建 `electron-builder --win`，不用 `--prepackaged`
- **状态**: ✅ 已修复

#### 问题7: 图标显示为旧版本（Windows 缓存）
- **现象**: exe 内嵌的是新图标，但桌面/任务栏仍显示旧图标
- **根因**: Windows 图标缓存（IconCache.db, iconcache_*.db）未刷新
- **修复**: 执行 `ie4uinit.exe -show`；如仍无效，重启电脑或手动删除 `%LOCALAPPDATA%\IconCache.db`
- **状态**: ✅ 已处理（验证 exe 内嵌图标为 32x32 有效图标）

### 2026-07-19 修复的问题（第二轮）

#### 问题8: 首次 Ctrl+B 启动悬浮框失败
- **现象**: 应用启动后按 Ctrl+B 无任何反应，悬浮框不出现
- **根因**: 鸡生蛋问题 — `registerGlobalShortcuts()` 只在 `launchExamClient()` 内调用，但 Ctrl+B 本身就是触发 `launchExamClient()` 的快捷键。应用启动时没有注册任何快捷键，因此 Ctrl+B 无效
- **修复**:
  1. 在 `initializeApp()` 中创建 `shortcutsHelper` 后立即调用 `registerGlobalShortcuts()`，确保启动时所有快捷键已注册
  2. `launchExamClient()` 中移除 `registerGlobalShortcuts()` 调用（避免重复注册）
  3. `handleWindowClosed()` 和 `closeExamClient()` 中移除 `unregisterAll()` 调用，保持 Ctrl+B 始终可用
- **状态**: ✅ 已修复

#### 问题9: 截图后调用 AI 失败
- **现象**: 截图后按搜题快捷键，AI 无响应，无错误提示
- **根因**: `ProcessingHelper.analyze()` 读取 `deviceId` 时从 `configHelper.getUserConfig().clientSettings?.deviceId` 取值，但 `AuthManager` 从未将 deviceId 写入 clientSettings（它存在独立的 `device-id.json` 文件中），导致请求中 `deviceId` 为空字符串，服务端可能拒绝
- **修复**:
  1. `AuthManager.init()` 中增加 `configHelper.updateClientSettings({ deviceId: this.deviceId })`，将 deviceId 同步到 clientSettings
  2. `ProcessingHelper.analyze()` 增加诊断日志（imageCount、imageLength、hasToken、deviceId、apiBaseUrl），便于排查
  3. `ProcessingHelper.analyze()` 错误分支增加 `console.error` 输出错误消息和 code
- **状态**: ✅ 已修复（需登录后实测验证）

#### 问题10: 调整大小快捷键配置错误
- **现象**: 调整高度/宽度的快捷键与用户预期不符
- **根因**: 默认快捷键配置不符合用户指定方案
- **修复**: 修改 `shared/shortcuts.ts` 默认绑定：
  - `resize_height_larger`: `Ctrl+Shift+Up`（调高）
  - `resize_height_smaller`: `Ctrl+Shift+Down`（调小高度）
  - `resize_width_smaller`: `Ctrl+Shift+Left`（调小宽度）
  - `resize_width_larger`: `Ctrl+Shift+Right`（调大宽度）
- **状态**: ✅ 已修复

#### 问题11: 搜题模式过多，配置 UI 交互繁琐

### 2026-07-19 修复的问题（第三轮）

#### 问题15: AI 调用 413 Payload Too Large
- **现象**: 截图后搜题，服务端返回 HTTP 413，AI 无响应
- **根因**: 腾讯云 CloudBase HTTP 触发器请求体限制 1MB；全屏 PNG 截图 base64 后可达 3-7MB，远超限制
- **修复**:
  1. `ScreenshotHelper.ts` 新增 `fileToCompressedBase64()` 动态压缩方法
  2. 压缩策略：依次尝试 [1600/1280/960/720 像素] × [80/60/45/30 质量] 组合，找到第一个 ≤ 380KB 的结果
  3. 保证 base64 后 < 510KB，JSON 整体 < 550KB，安全在 1MB 限制内
  4. `ipcHandlers.ts` 截图 IPC 改用 `fileToCompressedBase64()` 替代 `fileToBase64()`
  5. `apiClient.ts` 增强错误诊断：失败时打印 HTTP 状态码、code、error、bodyLen
- **状态**: ✅ 已修复（需登录后实测验证）
- **备注**: 不换阿里云，因为客户端压缩是行业标配，符合"重用原始软件包方法"约束，无需改服务端

#### 问题16: 快捷键配置不生效（旧配置覆盖新默认值）
- **现象**: 修改了 `shortcuts.ts` 默认值（Ctrl+Q/Ctrl+W），但用户机器上仍显示旧的 Ctrl+H/Ctrl+Enter；Ctrl+Shift+↑↓←→ 调整大小也不生效
- **根因**: `ShortcutsHelper.init()` 中 `{ ...defaultShortcutBindings, ...stored }` 会用用户持久化的旧配置覆盖新默认值。系统固定快捷键（resize 等）也被旧配置覆盖
- **修复**:
  1. `init()` 重写：只接受可配置项（screenshot/search）的用户存储值，系统固定快捷键一律用默认值
  2. 迁移逻辑：`stored.screenshot === 'Ctrl+H'` → `Ctrl+Q`，`stored.search === 'Ctrl+Enter'` → `Ctrl+W`（只迁移等于旧默认值的，不影响用户自定义）
  3. 持久化迁移结果，避免下次启动重复迁移
- **状态**: ✅ 已修复

#### 问题17: 不需要退出快捷键
- **现象**: 用户不需要 quit 快捷键（Ctrl+B 已可显示/隐藏，退出用托盘）
- **修复**: `registerGlobalShortcuts()` 中跳过 `quit` action 的注册，保留定义但不生效
- **状态**: ✅ 已修复

#### 问题18: 悬浮框快捷键提示不更新
- **现象**: 在配置页改了快捷键后，悬浮框顶部提示仍显示旧值
- **根因**: `config:set-shortcut-binding` 成功后没有向悬浮框广播变更事件
- **修复**: `ipcHandlers.ts` 新增 `broadcastToAllWindows()` 辅助函数，快捷键变更后向所有窗口（悬浮框+配置窗+登录窗）发送 `refresh-config` 事件，`OverlayPage.tsx` 已有监听器会刷新显示

## 九、对话与改动时间线（开发过程追溯）

> 本节整理了用户与开发者的完整对话与改动流程，便于追溯每个问题的来龙去脉。

### 阶段一：防捕获功能修复

**用户反馈**：
> 根据这个文件夹，帮我修复window的代码问题，现在我发现的问题是：我刚刚看到悬浮框了，但是悬浮框是不会被任何捕捉到的，应该是鼠标穿透，不能被截屏/录屏，也不会被监测到。有一些开源的技术方案我放在了新一代文件夹的这三个文件里面，你可以参考 DisableFlagSecure-main DisableFlagSecure-master EasyWindow-master

**分析与改动**：
- 参考 `DisableFlagSecure-main`、`DisableFlagSecure-master`、`EasyWindow-master` 三个开源方案
- 新建 `electron/Win32Protection.ts`，使用 koffi FFI 调用 Win32 API：
  - `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` — DWM 合成阶段排除捕获
  - `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE` — 不在任务栏/Alt+Tab 显示
  - 空标题 — 降低被监测风险
- 修复智能鼠标穿透：悬浮框空白区域穿透，按钮/滚动区域可交互

**首次报错**：
> A JavaScript error occurred in the main process Uncaught Exception: Error: Cannot find module './dist-electron/Win32Protection.js'

**修复**：TypeScript 文件未编译，运行 `vite build` 编译 electron TS 文件。

### 阶段二：生成安装包

**用户请求**：
> 生成一个安装包给我
> 生成的文件统一放在新一代文件夹下面，后续我需要整理的

**遇到的问题**：
1. **中文路径导致 7za.exe 失败**：`E:\ai项目\考试插件\...` 路径使 7za.exe 编码错误
   - **解决**：创建 junction `C:\QuizCozeBuild` → 目标路径
2. **exe 名为 electron.exe**：
   > 报错了，提示Windows正在查找QuizCoze.exe
   - **解决**：在 package.json 设置 `productName: "QuizCoze"`
3. **app.asar 被占用**：
   - **解决**：构建前 `Get-Process QuizCoze | Stop-Process -Force`

### 阶段三：核心功能修复

**用户反馈**：
> 几个核心的修改点：快捷键没有起作用，无论是调节悬浮框的透明度还是调节大小位置等，这几个快捷键是作用在悬浮框上的，是一个配置的后台，是对应调整悬浮框的。更关键的是启动截屏传说给ai没有起作用，应该启动全屏截图后，将图片传给后台ai，调用ai来返回答案。另外交互上，不需要从任务管理里面启动悬浮框，ctrl+B不就是启动和隐藏悬浮框的吗，通过这个来控制的，后台通过任务管理里面点开和隐藏，目前后台管理和悬浮不能同时出现，这两个不冲突，控制悬浮框的就是ctrl+B，和后台管理不冲突

**改动清单**（共 4 个文件）：

#### `electron/main.ts`
1. `launchExamClient()` — 移除 `closeEntryWindows()`，允许后台管理窗口保留
2. `createLoginWindow()` / `createConfigWindow()` — 移除 `overlayLocked` 守卫
3. `handleWindowClosed()` — 不再强制恢复配置窗口
4. 托盘 `toggleOverlay` — 改为显示/隐藏切换（与 Ctrl+B 一致），不再销毁
5. `showMainWindow()` — 立即同步 `processingHelper.setMainWindow()`
6. `processingHelper` 轮询间隔 1000ms → 200ms

#### `electron/ScreenshotHelper.ts`
- PowerShell 降级脚本补充 `Add-Type -AssemblyName System.Windows.Forms`

#### `electron/ProcessingHelper.ts`
- `checkCredits()` catch 块改为 `sufficient: true`，网络错误不阻止请求

#### `electron/ipcHandlers.ts`
- `screenshot:capture-full` 统一先隐藏悬浮框再截图

### 阶段四：打不开 + 图标回归（本次重点）

**用户反馈**：

**修复**：

2. 改用一次性构建：`node node_modules/electron-builder/cli.js --win`
3. 让 electron-builder 自己处理 asar 打包和图标嵌入
